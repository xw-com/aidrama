# 🎬 星网 XW.COM · پلتفرم تولید سریال‌های کوتاه با هوش مصنوعی

> 🌐 **دموی آنلاین**: <https://aiwork.xw.com> 　·　📮 تماس با ما: **kevin@xw.com**

یک سامانه کامل تولید درام کوتاه با هوش مصنوعی: **ورود فیلمنامه ← استخراج شخصیت‌ها/صحنه‌ها/پراپس ← تولید استوری‌بورد ← تولید ویدیوی هر سگمنت ← مونتاژ کل اپیزود**.
سمت سرور **Node.js + MySQL (با بازگشت خودکار به / SQLite)** است و سمت کاربر **Vue 3 + Element Plus** در دو نسخه: **وب (پوشه client، شامل پنل مدیریت client/admin و پوسته دسکتاپ client/desktop) + موبایل (uniapp، پوسته‌های App/مینی‌برنامه/H5)** که از طریق REST API با هم در ارتباط‌اند. سامانه حساب‌ها بر پایه **ثبت‌نام/ورود محلیِ درون‌ساخت** (نام کاربری/ایمیل/شماره موبایل + رمز عبور) است و به هیچ مرکز حساب شخص ثالثی وابسته نیست.

## 🚀 شروع سریع

### 1. راه‌اندازی سرور

```bash
cd server
cp .env.example .env          # پیش‌فرض DB_DIALECT=sqlite، بدون هیچ پیکربندی اجرا می‌شود
npm install
npm run dev                   # http://localhost:3000 ، با ساخت خودکار جدول‌ها + seed
```

- **SQLite (آماده به‌کار، برای تجربه محلی توصیه می‌شود)**: `DB_DIALECT=sqlite`، داده‌ها در `server/data/aidrama.db` ذخیره می‌شوند
- **MySQL**: مقدار `DB_DIALECT=mysql` را تنظیم و `DB_HOST/DB_PORT/DB_NAME/DB_USER/DB_PASSWORD` را پر کنید
- **مدیر اولیه هنگام اولین اجرا به‌طور خودکار ساخته می‌شود** (پیامی در کنسول چاپ خواهد شد):
  - حساب پیش‌فرض **`admin / admin123`**، برای ورود به پنل مدیریت `/admin`
  - با متغیرهای محیطی `ADMIN_INIT_USERNAME` / `ADMIN_INIT_PASSWORD` قابل تغییر است؛ اگر مدیر از قبل موجود باشد این مرحله نادیده گرفته می‌شود
  - ⚠️ پیش از راه‌اندازی در محیط عملیاتی، رمز پیش‌فرض را فوراً تغییر دهید (`node scripts/setAdminPassword.js`، یا بخش پنل مدیریت را در ادامه ببینید)

### 2. راه‌اندازی کلاینت

```bash
cd client
npm install
npm run dev                   # http://localhost:5173
```

<http://localhost:5173> را باز کنید: اگر حساب ندارید روی «ثبت‌نام» بزنید (نام کاربری + رمز عبور، به‌همراه یک کپچای انتخاب متن؛ پس از ثبت‌نام موفق، ورود انجام می‌شود و 66 اعتبار آزمایشی هدیه می‌گیرید)؛ اگر حساب دارید مستقیم وارد شوید (نام کاربری / ایمیل / شماره موبایل، هرکدام کافی است).

> کلاینت از قبل پروکسی تنظیم شده و `/api` و `/files` به‌طور خودکار به `http://localhost:3000` ارسال می‌شوند.

## 🛠 استفاده از پنل مدیریت (client/admin)

پنل مدیریت دارای **ورودی مستقل، ورود مستقل و توکن مستقل** است (توکن JWT با پیشوند `admt_`، که هیچ ارتباطی با نشست‌های کاربران نسخه اصلی ندارد):

- **ورودی**: <http://localhost:5173/admin> (در محیط عملیاتی `https://دامنه-شما/admin`)
- **ورود**: حساب + رمز عبور + کپچای انتخاب متن. در اولین اجرا از مدیر اولیه **`admin / admin123`** استفاده کنید؛
- **تغییر رمز**: فعلاً در پنل صفحه‌ای برای تغییر رمز وجود ندارد؛ با اسکریپت سمت سرور بازنشانی کنید:
  ```bash
  cd server
  node scripts/setAdminPassword.js <نام کاربری یا ایمیل> <رمز جدید>
  ```
  (ورود `adminAuth`، نام کاربری / ایمیل / شماره موبایل را به هر شکلی می‌پذیرد)

## 🔌 پیکربندی مدل‌های بزرگ / رسانه (برای اینکه قابلیت‌های هوش مصنوعی واقعاً کار کنند)

همه قابلیت‌های هوش مصنوعی **پیکربندی‌محور** هستند و **به‌طور متمرکز از صفحه «پیکربندی مدل‌ها» در پنل مدیریت مدیریت می‌شوند** (`.env` دیگر هیچ پیکربندی پیش‌فرض LLM ندارد). بدون پیکربندی: قابلیت‌های متنی پیش از فراخوانی هشدار می‌دهند؛ تصویر/ویدیو/TTS مستقیماً خطای «پیکربندی نشده» می‌دهند.

مراحل پیکربندی:

1. وارد پنل مدیریت `/admin` شوید ← **پیکربندی مدل‌ها** ← افزودن؛
2. دسته (متن / تصویر / ویدیو / TTS) و پروتکل را انتخاب و موارد زیر را پر کنید:
   - **Base URL** (مثل `https://api.openai.com/v1`)
   - **API Key** (فقط روی سرور ذخیره می‌شود و به فرانت‌اند ارسال نمی‌شود)
   - **نام مدل** (مثل `gpt-4o-mini` و `dall-e-3`)
   - وضعیت فعال بودن و قیمت اعتباری این پیکربندی؛
3. پس از ذخیره، بلافاصله در فرانت‌اند قابل استفاده است (برای یک دسته می‌توان چند پیکربندی داشت و با فعال/غیرفعال بین آن‌ها جابه‌جا شد)؛ صفحه «پیکربندی مدل‌ها» از **درون‌ریزی / برون‌بری JSON** نیز پشتیبانی می‌کند تا انتقال گروهی آسان شود.

پروتکل‌های پشتیبانی‌شده:

- **متن / تصویر / TTS**: سازگار با OpenAI (`/chat/completions` و `/images/generations` و `/audio/speech`) یا نقطه پایانی سفارشی (`api_style=custom`)
- **ویدیو**: نقطه پایانی وظایف ناهمگام پیکربندی می‌شود (ارسال ← پرس‌وجو ← URL ویدیو)؛ ارائه‌دهنده واقعی تولید ویدیو لازم است (قابلیت محلی «تبدیل تصویر به ویدیو» با ffmpeg غیرفعال شده است)

> کاربر همچنین می‌تواند از «تنظیمات شخصی ← مدل‌های من» **مدل خصوصی** اضافه کند (با Key خودش؛ فراخوانی‌هایش اعتبار کم نمی‌کند) و تأثیری بر پیکربندی سراسری ندارد.
> نصب محلی `ffmpeg` لازم است (در macOS: `brew install ffmpeg`). چسباندن و مونتاژ سگمنت‌های ویدیویی به آن وابسته است.

## 🚢 استقرار در محیط عملیاتی

راهنمای اجرایی کامل در **[deploy/DEPLOY.md](deploy/DEPLOY.md)** است (چک‌لیست راه‌اندازی با nginx، PM2/systemd با تک‌نمونه، پشتیبان‌گیری و بازیابی، راه‌اندازی WeChat Pay، و کارهای در دستور انطباق). حداقل الزامات محیط:

```bash
NODE_ENV=production            # اگر تنظیم نشود، کلید پیش‌فرض توسعه‌ای JWT فعال می‌شود؛ ریسک امنیتی
JWT_SECRET=<کلید امضای توکن نشست محلی، رشته تصادفی بلند>      # این سیستم امضای نشست کاربران و اعتبارسنجی آن را خودش انجام می‌دهد (axt_)
ADMIN_JWT_SECRET=<کلید امضای مستقل پنل مدیریت>
FILE_SIGN_SECRET=<کلید امضای محافظت رسانه از hotlink>   # باید با کلید secure_link در deploy/nginx.conf یکسان باشد
PUBLIC_BASE_URL=https://your-domain.com
CLIENT_ORIGIN=https://your-domain.com
DB_DIALECT=mysql               # + DB_HOST/DB_PORT/DB_NAME/DB_USER/DB_PASSWORD
```

برای WeChat Pay به‌علاوه مجموعه پنج‌تایی `WECHAT_PAY_*` لازم است (شناسه پذیرنده، AppID، کلید APIv3، شماره سریال گواهی، کلید خصوصی پذیرنده)؛ رجوع شود به `deploy/DEPLOY.md` ⑦.

## 🔑 ورود و سامانه حساب‌ها (محلی، بدون وابستگی خارجی)

سامانه حساب‌ها **درون‌ساختِ همین سیستم** است: ثبت‌نام / ورود / تغییر رمز / تازه‌سازی نشست، همگی از طریق `/api/auth/*` روی همین سرور انجام می‌شود و به هیچ مرکز حساب شخص ثالثی وابسته نیست:

- **ثبت‌نام**: نام کاربری (2-64 نویسه: حروف لاتین، ارقام و `_.-`) + رمز عبور (۶ نویسه یا بیشتر) + ایمیل (اختیاری)، همراه با کپچای انتخاب متن الزامی (طرح سؤال به‌صورت SVG از سمت سرور، `/api/captcha/*`)؛ ثبت‌نام موفق یعنی ورود خودکار و هدیه 66 اعتبار آزمایشی؛
- **ورود**: نام کاربری / ایمیل / شماره موبایل (هرکدام) + رمز عبور؛ کپچا «فقط اگر ارسال شود اعتبارسنجی می‌شود» (فرانت‌اند به‌طور پیش‌فرض ارسال می‌کند)؛
- **توکن‌ها**: سرور خودش JWT امضا می‌کند (پیشوند `axt_`، شامل access + refresh بدون چرخش refresh)؛ فرانت‌اند بی‌صدا از `/api/auth/oauth/refresh` تمدید می‌کند؛ توکن پنل مدیریت جدا است (پیشوند `admt_`)؛
- **فراموشی رمز**: در نمونه‌های خودمیزبان کانال SMS/ایمیل وجود ندارد و بازیابی خودسرانه فراهم نیست — این کار توسط مدیر از **پنل مدیریت «مدیریت کاربران» ← بازنشانی رمز عبور** انجام می‌شود؛
- **مسدودسازی**: پس از مسدودسازی، همه توکن‌های صادرشده کاربر در نخستین درخواست بعدی باطل می‌شوند (سرور در هر درخواست وضعیت کاربر را دوباره بررسی می‌کند)؛
- **ورود با شخص ثالث (اختیاری)**: ورود یک‌کلیکی Apple / Google در اپ موبایل همچنان کار می‌کند — سرور با نگه‌داشتن کلیدها، تبادل را به‌عنوان واسطه انجام می‌دهد (`POST /api/auth/oauth/:provider`) و همان نشست محلی `axt_` را برمی‌گرداند؛ نسخه وب به هیچ ثبت callback نیاز ندارد.

متغیرهای `.env` مرتبط: `JWT_SECRET`، `ADMIN_JWT_SECRET`، `CAPTCHA_TICKET_SECRET`، `ADMIN_INIT_USERNAME`، `ADMIN_INIT_PASSWORD` (همگی در توضیحات `server/.env.example`).

## 💚 WeChat Pay (V3 · اسکن کد Native / JSAPI)

WeChat Pay واقعی، **پیکربندی‌محور و به‌طور پیش‌فرض خاموش** (اگر `WECHAT_PAY_*` در `.env` خالی بماند فعال نیست و فرانت‌اند ورودی شارژ را خودکار پنهان می‌کند). مقدار `WECHAT_APP_ID` فقط به‌عنوان مقدار جایگزین AppID پرداخت باقی مانده است.

در [پلتفرم پذیرندگان WeChat](https://pay.weixin.qq.com/) پرداخت Native/JSAPI را فعال کنید، شناسه پذیرنده و کلید APIv3 را دریافت و گواهی API پذیرنده را دانلود کنید (`apiclient_key.pem` + شماره سریال گواهی). **اتصال شناسه پذیرنده و AppID باید روی پلتفرم پذیرنده کامل شود** (در غیر این صورت ثبت سفارش با خطای `APPID_MCHID_NOT_MATCH` شکست می‌خورد). پیکربندی:
```bash
WECHAT_PAY_METHOD=native       # native=اسکن کد QR | jsapi=پرداخت داخل اکانت رسمی (PC از صندوق H5 می‌گذرد)
WECHAT_PAY_APP_ID=             # AppID متصل به شناسه پذیرنده (در صورت خالی بودن، به WECHAT_APP_ID برمی‌گردد)
WECHAT_PAY_MCH_ID=<شناسه پذیرنده شما>
WECHAT_PAY_API_V3_KEY=         # کلید APIv3 با طول 32 نویسه
WECHAT_PAY_SERIAL_NO=          # شماره سریال گواهی API پذیرنده
WECHAT_PAY_PRIVATE_KEY_PATH=cert/apiclient_key.pem   # مسیر فایل apiclient_key.pem روی دیسک (یکی از این سطر یا سطر بعدی)
WECHAT_PAY_PRIVATE_KEY=        # یا مستقیماً متن PEM به‌صورت درون‌خطی
WECHAT_PAY_NOTIFY_URL=         # در صورت خالی بودن، ${PUBLIC_BASE_URL}/api/recharge/wechat/notify گرفته می‌شود
```
- مسیر: در مرکز اعتبار «WeChat Pay» را انتخاب کنید ← سرور سفارش یکپارچه ثبت می‌کند (Native مقدار `code_url` را برای نمایش کد QR برمی‌گرداند / JSAPI پرداخت را فرامی‌خواند) ← کاربر پرداخت می‌کند ← فراخوانی ناهمگام WeChat روی `/api/recharge/wechat/notify` (اعتبارسنجی و رمزگشایی AES-256-GCM، و ثبت اعتبار به‌صورت idempotent).
- نشانی فراخوانی باید **نشانی HTTPS در دسترس از اینترنت عمومی** باشد (در زمان توسعه می‌توان از تونل شبکه داخلی استفاده کرد).

> مراحل راه‌اندازی (اتصال AppID در پلتفرم پذیرنده، قرار دادن گواهی روی سرور، و رگرسیون با یک سفارش واقعی به ارزش یک سنت) را در **[deploy/DEPLOY.md](deploy/DEPLOY.md) ⑦ مراحل راه‌اندازی WeChat Pay** ببینید.
> دیتابیس: شماره تراکنش سفارش پرداخت در `recharge_orders.transaction_id` نوشته می‌شود و هنگام راه‌اندازی به‌صورت idempotent توسط `ensureColumns` تکمیل می‌شود، بدون اثر بر دیتابیس‌های قدیمی.

## 🧪 مراحل راستی‌آزمایی از ابتدا تا انتها

0. پنل مدیریت `/admin` (admin/admin123) ← **پیکربندی مدل‌ها** ← هر چهار دستهٔ متن/تصویر/ویدیو/TTS را پیکربندی کنید (در غیر این صورت مراحل هوش مصنوعی در دسترس نیستند)
1. ثبت‌نام/ورود در فرانت‌اند ← پروژه جدید ← «طرح کلی فیلمنامه»: چسباندن/بارگذاری فیلمنامه ← **تقسیم فیلمنامه با هوش مصنوعی** (اعتبار کسر می‌شود)
2. «کتابخانه دارایی‌ها» ← **استخراج دارایی با هوش مصنوعی** ← **تولید تصویر دارایی** برای شخصیت‌ها/صحنه‌ها
3. «ویدیوی اپیزودها» ← **تولید متن** ← ورود به **ویرایشگر استوری‌بورد**
4. داخل ویرایشگر یک سگمنت را انتخاب کنید ← **تولید فوری** (ویدیوی سگمنت، همراه با استخراج خودکار فریم اول به‌عنوان کاور پیش‌نمایش)
5. **مونتاژ کل اپیزود** (ffmpeg کل اپیزود را به mp4 می‌چسباند)
6. در «مرکز اعتبار» گردش حساب را ببینید و شارژ کنید؛ در پنل مدیریت قیمت‌ها را تغییر دهید / مسدود کنید / رمز را بازنشانی کنید / گزارش ورود را ببینید؛ و پوسته را بین روشن/تاریک/خودکار جابه‌جا کنید

## 📡 APIهای اصلی (با پیشوند `/api`، احراز هویت JWT، و قالب یکسان `{code,message,data}`)

```
POST /auth/register | /auth/login                              # ثبت‌نام محلی (ticket کپچا لازم است) / ورود (عمومی، با محدودیت نرخ)
POST /auth/password                                            # تغییر رمز عبور (با وضعیت ورود)
POST /auth/oauth/refresh                                       # تمدید بی‌صدا (تبدیل refresh_token به access_token جدید، عمومی)
POST /auth/oauth/:provider                                     # تبادل ورود شخص ثالث با نشست محلی (apple/google/weixin/huawei، اختیاری)
GET /auth/me   POST /auth/sync                                 # پروفایل کاربر
POST /captcha/challenge | /captcha/verify                      # کپچای انتخاب متن
GET/POST/PUT/DELETE /projects          GET /projects/:id
POST /projects/:id/script/import       POST /projects/:id/script/parse
POST /projects/:id/extract             GET /projects/:id/assets  POST /assets/:id/generate-image
POST /episodes/:id/generate-storyboard GET /episodes/:id/segments
POST /segments/:id/generate            PUT /segments/:id
POST /episodes/:id/compose             GET /episodes/:id/video
GET /jobs                                                              # مرکز وظایف ناهمگام (فرانت‌اند پرس‌وجو می‌کند)
GET /model-configs                     POST /model-configs/import  GET /model-configs/export   # سمت خواندن پیکربندی سراسری + درون‌ریزی/برون‌بری (از پنل مدیریت مدیریت می‌شود)
GET /credits/balance | /credits/transactions
GET /recharge/packages  POST /recharge/create  GET /recharge/orders/:id
POST /recharge/wechat/notify                                   # فراخوانی WeChat Pay (بدون احراز هویت، اعتبارسنجی امضا + idempotent)
GET /showcase/*                                                # مرکز نمایشگاه (انتشار/مرور/بساز مثلش)
GET /market/*                                                  # مرکز سفارش‌گیری (سفارش کار/امانی/تحویل و پذیرش)
GET /pricing
```
هر API هوش مصنوعی، API متناظر `…/estimate` برای برآورد اعتبار دارد؛ APIهای مدیریتی (`/admin/*`: کاربران/پرداخت‌ها/وظایف/گزارش‌ها/نگهداری و غیره) از توکن مدیریتی مستقل (`admt_`) استفاده می‌کنند.
