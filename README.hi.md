# 🎬 星网 XW.COM · AI शॉर्ट-ड्रामा निर्माण प्लेटफ़ॉर्म

> 🌐 **ऑनलाइन डेमो**: <https://aiwork.xw.com> 　·　📮 हमसे संपर्क करें: **kevin@xw.com**

AI से शॉर्ट-ड्रामा बनाने की एक संपूर्ण प्रणाली: **स्क्रिप्ट इंपोर्ट → किरदार/सीन/प्रॉप्स निकालना → स्टोरीबोर्ड जनरेट करना → स्टोरीबोर्ड वीडियो जनरेट करना → पूरा एपिसोड कंपोज़ करना**।
सर्वर **Node.js + MySQL (/ SQLite फ़ॉलबैक)** पर, फ्रंटएंड **Vue 3 + Element Plus** के दो पक्ष: **Web (client, जिसमें एडमिन पैनल client/admin और डेस्कटॉप शेल client/desktop शामिल हैं) + मोबाइल (uniapp, App/मिनी-प्रोग्राम शेल/H5)** — ये REST API से आपस में बात करते हैं। अकाउंट सिस्टम **बिल्ट-इन लोकल रजिस्ट्रेशन/लॉगिन** (यूज़रनेम/ईमेल/मोबाइल नंबर + पासवर्ड) पर आधारित है, किसी थर्ड-पार्टी अकाउंट सेंटर पर निर्भर नहीं।

## 🚀 तेज़ शुरुआत

### 1. सर्वर शुरू करें

```bash
cd server
cp .env.example .env          # डिफ़ॉल्ट DB_DIALECT=sqlite — बिना किसी कॉन्फ़िगरेशन के चल जाता है
npm install
npm run dev                   # http://localhost:3000 , टेबल अपने-आप बनती हैं + seed
```

- **SQLite (बॉक्स से बाहर तैयार, लोकल इस्तेमाल के लिए सुझाया गया)**: `DB_DIALECT=sqlite`, डेटा `server/data/aidrama.db` में सुरक्षित होता है
- **MySQL**: `DB_DIALECT=mysql` सेट करें और `DB_HOST/DB_PORT/DB_NAME/DB_USER/DB_PASSWORD` भरें
- **पहली बार चलाने पर प्रारंभिक एडमिन अपने-आप बन जाता है** (कंसोल में संकेत छपेगा):
  - डिफ़ॉल्ट अकाउंट **`admin / admin123`**, जो एडमिन पैनल `/admin` में लॉगिन के काम आता है
  - एनवायरनमेंट वेरिएबल `ADMIN_INIT_USERNAME` / `ADMIN_INIT_PASSWORD` से बदला जा सकता है; एडमिन पहले से मौजूद हो तो यह चरण छोड़ दिया जाता है
  - ⚠️ प्रोडक्शन में जाने से पहले डिफ़ॉल्ट पासवर्ड तुरंत बदलें (`node scripts/setAdminPassword.js`, या नीचे एडमिन पैनल वाला सेक्शन देखें)

### 2. क्लाइंट शुरू करें

```bash
cd client
npm install
npm run dev                   # http://localhost:5173
```

<http://localhost:5173> खोलें: अकाउंट नहीं है तो 「रजिस्टर」 दबाएँ (यूज़रनेम + पासवर्ड, टेक्स्ट-चयन CAPTCHA पार करनी है; रजिस्ट्रेशन सफल होते ही लॉगिन हो जाता है और 66 ट्रायल क्रेडिट मिलते हैं); अकाउंट पहले से है तो सीधे लॉगिन करें (यूज़रनेम / ईमेल / मोबाइल नंबर कोई भी चलेगा)।

> क्लाइंट में प्रॉक्सी पहले से कॉन्फ़िगर है — `/api` और `/files` अपने-आप `http://localhost:3000` पर फ़ॉरवर्ड हो जाते हैं।

## 🛠 एडमिन पैनल (client/admin) उपयोग

एडमिन पैनल **अलग एंट्री, अलग लॉगिन, अलग टोकन** वाला है (`admt_` प्रीफ़िक्स वाला JWT, फ्रंटएंड यूज़र सेशन से कोई संबंध नहीं):

- **एंट्री**: <http://localhost:5173/admin> (प्रोडक्शन में `https://आपका-डोमेन/admin`)
- **लॉगिन**: अकाउंट + पासवर्ड + टेक्स्ट-चयन CAPTCHA। पहली बार प्रारंभिक एडमिन **`admin / admin123`** इस्तेमाल करें;
- **पासवर्ड बदलना**: पैनल में अभी पासवर्ड-बदलने का पेज नहीं है, सर्वर स्क्रिप्ट से रीसेट करें:
  ```bash
  cd server
  node scripts/setAdminPassword.js <यूज़रनेम या ईमेल> <नया पासवर्ड>
  ```
  (`adminAuth` लॉगिन में यूज़रनेम / ईमेल / मोबाइल नंबर में से कोई भी अकाउंट के रूप में चलेगा)

## 🔌 LLM / मीडिया कॉन्फ़िगर करना (AI फ़ीचर्स को सच में काम करने के लिए)

सभी AI क्षमताएँ **कॉन्फ़िगरेशन-संचालित** हैं और **एडमिन पैनल के 「मॉडल कॉन्फ़िगरेशन」 पेज से केंद्रीय रूप से मैनेज होती हैं** (`.env` अब कोई डिफ़ॉल्ट LLM कॉन्फ़िगरेशन नहीं देता)। कॉन्फ़िगर न होने पर: टेक्स्ट फ़ीचर कॉल से पहले संकेत देते हैं; इमेज/वीडियो/TTS सीधे 「कॉन्फ़िगर नहीं」 की एरर देते हैं।

कॉन्फ़िगरेशन के चरण:

1. एडमिन पैनल `/admin` में लॉगिन करें → **मॉडल कॉन्फ़िगरेशन** → जोड़ें;
2. श्रेणी (टेक्स्ट / इमेज / वीडियो / TTS) और प्रोटोकॉल चुनें, फिर भरें:
   - **Base URL** (जैसे `https://api.openai.com/v1`)
   - **API Key** (सिर्फ़ सर्वर पर सुरक्षित रहता है, फ्रंटएंड को नहीं भेजा जाता)
   - **मॉडल का नाम** (जैसे `gpt-4o-mini`, `dall-e-3`)
   - चालू स्थिति और इस कॉन्फ़िगरेशन की क्रेडिट कीमत;
3. सेव करते ही फ्रंटएंड में उपलब्ध (एक ही श्रेणी की कई कॉन्फ़िगरेशन रखकर चालू/बंद से बदला जा सकता है); 「मॉडल कॉन्फ़िगरेशन」 पेज **JSON इंपोर्ट / एक्सपोर्ट** भी सपोर्ट करता है, जिससे बैच माइग्रेशन आसान होती है।

सपोर्टेड प्रोटोकॉल:

- **टेक्स्ट / इमेज / TTS**: OpenAI-कम्पैटिबल (`/chat/completions`, `/images/generations`, `/audio/speech`) या कस्टम एंडपॉइंट (`api_style=custom`)
- **वीडियो**: एसिंक्रोनस टास्क एंडपॉइंट कॉन्फ़िगर करें (सबमिट → पोल → वीडियो URL); असली वीडियो जनरेशन provider ज़रूरी है (लोकल ffmpeg 「इमेज-से-वीडियो」 बंद कर दिया गया है)

> यूज़र 「पर्सनल सेटिंग्स → माय मॉडल्स」 से **प्राइवेट मॉडल** भी जोड़ सकता है (अपनी Key के साथ; इसके कॉल पर क्रेडिट नहीं कटते), ग्लोबल कॉन्फ़िगरेशन पर इसका कोई असर नहीं।
> लोकली `ffmpeg` इंस्टॉल होना ज़रूरी है (macOS: `brew install ffmpeg`)। वीडियो सेगमेंट्स जोड़कर कंपोज़ करना इसी पर निर्भर है।

```bash
JWT_SECRET=<लोकल सेशन टोकन साइनिंग की, लंबी रैंडम स्ट्रिंग>      # यह सिस्टम यूज़र सेशन खुद साइन/वेरिफ़ाई करता है (axt_)
ADMIN_JWT_SECRET=<एडमिन पैनल की अलग साइनिंग की>
FILE_SIGN_SECRET=<मीडिया हॉटलिंक-रोकथाम साइनिंग की>   # deploy/nginx.conf के secure_link की से मैच होना ज़रूरी
PUBLIC_BASE_URL=https://your-domain.com
CLIENT_ORIGIN=https://your-domain.com
DB_DIALECT=mysql               # + DB_HOST/DB_PORT/DB_NAME/DB_USER/DB_PASSWORD
```

WeChat Pay के लिए अलग से `WECHAT_PAY_*` के पाँच आइटम चाहिए (मर्चेंट ID, AppID, APIv3 की, सर्टिफ़िकेट सीरियल नंबर, मर्चेंट प्राइवेट की), देखें `deploy/DEPLOY.md` ⑦।

## 🔑 लॉगिन और अकाउंट सिस्टम (लोकल, बाहरी निर्भरता रहित)

अकाउंट सिस्टम **इस सिस्टम में बिल्ट-इन** है: रजिस्ट्रेशन / लॉगिन / पासवर्ड बदलना / सेशन रिफ़्रेश — सब इसी सर्वर के `/api/auth/*` से होता है, किसी थर्ड-पार्टी अकाउंट सेंटर पर निर्भर नहीं:

- **रजिस्ट्रेशन**: यूज़रनेम (2-64 अक्षर — Latin अक्षर, अंक, `_.-`) + पासवर्ड (≥6 अक्षर) + ईमेल (वैकल्पिक), टेक्स्ट-चयन CAPTCHA ज़रूरी (बैकएंड SVG प्रश्न बनाता है, `/api/captcha/*`); रजिस्ट्रेशन सफल होते ही लॉगिन और 66 ट्रायल क्रेडिट;
- **लॉगिन**: यूज़रनेम / ईमेल / मोबाइल नंबर में से कोई एक + पासवर्ड; CAPTCHA 「देने पर ही जाँच」 (फ्रंटएंड डिफ़ॉल्ट रूप से भेजता है);
- **टोकन**: सर्वर खुद JWT साइन करता है (`axt_` प्रीफ़िक्स, access + refresh, refresh रोटेट नहीं होता), फ्रंटएंड चुपचाप `/api/auth/oauth/refresh` से रिन्यू करता है; एडमिन पैनल का टोकन अलग (`admt_` प्रीफ़िक्स);
- **पासवर्ड भूल गए**: सेल्फ़-डिप्लॉय इंस्टेंस में SMS/ईमेल चैनल नहीं होते, इसलिए सेल्फ़-सर्विस रीसेट नहीं — एडमिन **एडमिन पैनल 「यूज़र मैनेजमेंट」 → पासवर्ड रीसेट** से करता है;
- **बैन**: बैन के बाद यूज़र के सभी जारी किए गए टोकन अगले ही रिक्वेस्ट पर अमान्य (सर्वर हर रिक्वेस्ट पर यूज़र स्टेटस दोबारा जाँचता है);
- **थर्ड-पार्टी लॉगिन (वैकल्पिक)**: मोबाइल App का Apple / Google वन-क्लिक लॉगिन अब भी उपलब्ध — सर्वर key होल्ड करके प्रॉक्सी से एक्सचेंज करता है (`POST /api/auth/oauth/:provider`) और वही लोकल `axt_` सेशन लौटाता है; Web के लिए कोई callback रजिस्ट्रेशन ज़रूरी नहीं।

संबंधित `.env`: `JWT_SECRET`, `ADMIN_JWT_SECRET`, `CAPTCHA_TICKET_SECRET`, `ADMIN_INIT_USERNAME`, `ADMIN_INIT_PASSWORD` (सब `server/.env.example` के कमेंट में)।

## 💚 WeChat Pay (V3 · Native QR स्कैन / JSAPI)

असली WeChat Pay, **कॉन्फ़िगरेशन-संचालित, डिफ़ॉल्ट रूप से बंद** (`.env` में `WECHAT_PAY_*` खाली छोड़ें तो चालू नहीं होता, फ्रंटएंड रिचार्ज एंट्री अपने-आप छिपा देता है)। `WECHAT_APP_ID` सिर्फ़ पेमेंट AppID के फ़ॉलबैक के रूप में रखा गया है।

[WeChat मर्चेंट प्लेटफ़ॉर्म](https://pay.weixin.qq.com/) पर Native/JSAPI पेमेंट चालू करें, मर्चेंट ID और APIv3 की लें, और मर्चेंट API सर्टिफ़िकेट डाउनलोड करें (`apiclient_key.pem` + सर्टिफ़िकेट सीरियल नंबर)। **मर्चेंट ID और AppID का बाइंडिंग मर्चेंट प्लेटफ़ॉर्म पर पूरा होना ज़रूरी** (वरना ऑर्डर पर `APPID_MCHID_NOT_MATCH` एरर आता है)। कॉन्फ़िगरेशन:
```bash
WECHAT_PAY_METHOD=native       # native=QR स्कैन | jsapi=ऑफ़िशियल अकाउंट के अंदर पेमेंट (PC, H5 कैशियर से जाता है)
WECHAT_PAY_APP_ID=             # मर्चेंट ID से बंधा AppID (खाली छोड़ें तो WECHAT_APP_ID पर फ़ॉलबैक)
WECHAT_PAY_MCH_ID=<आपकी मर्चेंट ID>
WECHAT_PAY_API_V3_KEY=         # 32 अक्षरों की APIv3 की
WECHAT_PAY_SERIAL_NO=          # मर्चेंट API सर्टिफ़िकेट सीरियल नंबर
WECHAT_PAY_PRIVATE_KEY_PATH=cert/apiclient_key.pem   # apiclient_key.pem का डिस्क पथ (अगली लाइन में से एक चुनें)
WECHAT_PAY_PRIVATE_KEY=        # या सीधे PEM टेक्स्ट इनलाइन दें
WECHAT_PAY_NOTIFY_URL=         # खाली छोड़ें तो ${PUBLIC_BASE_URL}/api/recharge/wechat/notify लिया जाता है
```
- प्रक्रिया: क्रेडिट सेंटर में 「WeChat Pay」 चुनें → बैकएंड यूनिफ़ाइड ऑर्डर बनाता है (Native `code_url` लौटाता है जिससे QR रेंडर होता है / JSAPI पेमेंट उठाता है) → यूज़र पेमेंट करता है → WeChat का एसिंक्रोनस कॉलबैक `/api/recharge/wechat/notify` पर (AES-256-GCM डिक्रिप्ट-वेरिफ़िकेशन, इडेम्पोटेंट क्रेडिट एंट्री)।
- कॉलबैक **सार्वजनिक रूप से पहुँच योग्य HTTPS पता** होना चाहिए (डेवलपमेंट के दौरान इंट्रानेट टनलिंग चल सकती है)।

> लॉन्च के चरण (मर्चेंट प्लेटफ़ॉर्म पर AppID बाइंड करना, सर्टिफ़िकेट सर्वर पर लोकल रखना, एक पैसे के असली ऑर्डर से रिग्रेशन टेस्ट) — **[deploy/DEPLOY.md](deploy/DEPLOY.md) ⑦ WeChat Pay लॉन्च चरण** देखें।
> डेटाबेस: पेमेंट ऑर्डर का ट्रांज़ैक्शन नंबर `recharge_orders.transaction_id` में लिखा जाता है, जिसे स्टार्टअप पर `ensureColumns` इडेम्पोटेंट तरीके से जोड़ता है — पुराने डेटाबेस पर असर नहीं।

## 🧪 एंड-टू-एंड सत्यापन चरण

0. एडमिन पैनल `/admin` (admin/admin123) → **मॉडल कॉन्फ़िगरेशन** → टेक्स्ट/इमेज/वीडियो/TTS चारों श्रेणियाँ कॉन्फ़िगर करें (वरना AI चरण उपलब्ध नहीं)
1. फ्रंटएंड में रजिस्टर/लॉगिन → नया प्रोजेक्ट → 「स्क्रिप्ट आउटलाइन」 में स्क्रिप्ट पेस्ट/अपलोड → **AI स्क्रिप्ट विभाजन** (क्रेडिट कटते हैं)
2. 「असेट लाइब्रेरी」 → **AI असेट निकालना** → किरदार/सीन के लिए **असेट इमेज जनरेट** करें
3. 「एपिसोड वीडियो」 → **स्क्रिप्ट जनरेट** → **स्टोरीबोर्ड एडिटर** में जाएँ
4. एडिटर में सेगमेंट चुनें → **अभी जनरेट करें** (वीडियो सेगमेंट, और पहला फ़्रेम अपने-आप प्रीव्यू कवर बनता है)
5. **पूरा एपिसोड कंपोज़** (ffmpeg पूरे एपिसोड का mp4 बनाता है)
6. 「क्रेडिट सेंटर」 में लेन-देन देखें और रिचार्ज करें; एडमिन पैनल में प्राइसिंग बदलें / बैन करें / पासवर्ड रीसेट करें / लॉगिन लॉग देखें; लाइट/डार्क/ऑटो थीम बदलें

## 📡 मुख्य API (`/api` प्रीफ़िक्स, JWT ऑथेंटिकेशन, यूनिफ़ॉर्म `{code,message,data}`)

```
POST /auth/register | /auth/login                              # लोकल रजिस्ट्रेशन (CAPTCHA ticket ज़रूरी) / लॉगिन (सार्वजनिक, रेट-लिमिटेड)
POST /auth/password                                            # पासवर्ड बदलना (लॉगिन स्थिति)
POST /auth/oauth/refresh                                       # चुपचाप रिन्यू (refresh_token से नया access_token, सार्वजनिक)
POST /auth/oauth/:provider                                     # थर्ड-पार्टी लॉगिन से लोकल सेशन (apple/google/weixin/huawei, वैकल्पिक)
GET /auth/me   POST /auth/sync                                 # यूज़र प्रोफ़ाइल
POST /captcha/challenge | /captcha/verify                      # टेक्स्ट-चयन CAPTCHA
GET/POST/PUT/DELETE /projects          GET /projects/:id
POST /projects/:id/script/import       POST /projects/:id/script/parse
POST /projects/:id/extract             GET /projects/:id/assets  POST /assets/:id/generate-image
POST /episodes/:id/generate-storyboard GET /episodes/:id/segments
POST /segments/:id/generate            PUT /segments/:id
POST /episodes/:id/compose             GET /episodes/:id/video
GET /jobs                                                              # एसिंक्रोनस टास्क सेंटर (फ्रंटएंड पोल करता है)
GET /model-configs                     POST /model-configs/import  GET /model-configs/export   # ग्लोबल कॉन्फ़िगरेशन रीड साइड + इंपोर्ट/एक्सपोर्ट (एडमिन पैनल मैनेज करता है)
GET /credits/balance | /credits/transactions
GET /recharge/packages  POST /recharge/create  GET /recharge/orders/:id
POST /recharge/wechat/notify                                   # WeChat Pay कॉलबैक (ऑथ की ज़रूरत नहीं, साइन वेरिफ़िकेशन + इडेम्पोटेंट)
GET /showcase/*                                                # शोकेस सेंटर (प्रकाशित/ब्राउज़/वैसा ही बनाएँ)
GET /market/*                                                  # ऑर्डर सेंटर (टास्क ऑर्डर/एस्क्रो/स्वीकृति)
GET /pricing
```
हर AI एंडपॉइंट का एक संगत `…/estimate` एंडपॉइंट है जो क्रेडिट का अनुमान देता है; एडमिन एंडपॉइंट (`/admin/*`: यूज़र/पेमेंट/टास्क/लॉग/मेंटेनेंस आदि) अलग एडमिन टोकन (`admt_`) उपयोग करते हैं।
