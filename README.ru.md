# 🎬 星网 XW.COM · AI-платформа производства коротких драм (short drama)

> 🌐 **Онлайн-демо**: <https://aiwork.xw.com> 　·　📮 Связаться с нами: **kevin@xw.com**

Полноценная система создания коротких драм (short drama) с помощью ИИ: **импорт сценария → извлечение персонажей/сцен/реквизита → генерация раскадровки → генерация видео по раскадровке → сборка полного эпизода**.
Серверная часть — **Node.js + MySQL (с откатом на SQLite)**, фронтенд на **Vue 3 + Element Plus** в двух вариантах: **Web (client, включая админ-панель client/admin и десктоп-оболочку client/desktop) + мобильный (uniapp, оболочки App/мини-программа/H5)** — общение через REST API. Система аккаунтов — **встроенные локальные регистрация/вход** (имя пользователя/email/телефон + пароль), без зависимости от сторонних центров аккаунтов.

## 🚀 Быстрый старт

### 1. Запуск сервера

```bash
cd server
cp .env.example .env          # по умолчанию DB_DIALECT=sqlite — работает без всякой настройки
npm install
npm run dev                   # http://localhost:3000, автоматическое создание таблиц + seed
```

- **SQLite (работает из коробки, рекомендуем для локального знакомства)**: `DB_DIALECT=sqlite`, данные хранятся в `server/data/aidrama.db`
- **MySQL**: задайте `DB_DIALECT=mysql` и заполните `DB_HOST/DB_PORT/DB_NAME/DB_USER/DB_PASSWORD`
- **При первом запуске автоматически создаётся начальный администратор** (в консоль выводится подсказка):
  - учётная запись по умолчанию **`admin / admin123`**, для входа в админ-панель `/admin`
  - можно переопределить переменными окружения `ADMIN_INIT_USERNAME` / `ADMIN_INIT_PASSWORD`; если администратор уже существует, шаг пропускается
  - ⚠️ перед выходом в продакшен сразу смените пароль по умолчанию (`node scripts/setAdminPassword.js`, либо см. раздел об админ-панели ниже)

### 2. Запуск клиента

```bash
cd client
npm install
npm run dev                   # http://localhost:5173
```

Откройте <http://localhost:5173>: если аккаунта нет — нажмите «Регистрация» (имя пользователя + пароль, пройдите капчу с выбором текста; после успешной регистрации вы сразу вошли и получаете в подарок 66 пробных кредитов); если аккаунт есть — просто войдите (подойдёт имя пользователя / email / телефон).

> В клиенте уже настроен прокси: `/api` и `/files` автоматически пробрасываются на `http://localhost:3000`.

## 🛠 Работа с админ-панелью (client/admin)

Админ-панель — это **отдельный вход, отдельный логин, отдельный токен** (JWT с префиксом `admt_`, никак не пересекается с пользовательскими сессиями фронтенда):

- **Адрес входа**: <http://localhost:5173/admin> (в продакшене — `https://ваш-домен/admin`)
- **Логин**: аккаунт + пароль + капча с выбором текста. При первом запуске используйте начального администратора **`admin / admin123`**;
- **Смена пароля**: отдельной страницы смены пароля в панели пока нет, используйте серверный скрипт:
  ```bash
  cd server
  node scripts/setAdminPassword.js <имя пользователя или email> <новый пароль>
  ```
  (вход через `adminAuth` принимает в качестве аккаунта имя пользователя / email / телефон)

## 🔌 Настройка LLM / медиа (чтобы функции ИИ реально заработали)

Все возможности ИИ — **управляемые конфигурацией**, и **единое место их настройки — страница «Настройка моделей» в админ-панели** (`.env` больше не предоставляет никаких конфигураций LLM по умолчанию). Если ничего не настроено: текстовые функции предупредят перед вызовом; изображения/видео/TTS сразу вернут ошибку «не настроено».

Шаги настройки:

1. Войдите в админ-панель `/admin` → **Настройка моделей** → добавить;
2. выберите тип (текст / изображения / видео / TTS) и протокол, заполните:
   - **Base URL** (например `https://api.openai.com/v1`)
   - **API Key** (хранится только на сервере и не передаётся на фронтенд)
   - **Название модели** (например `gpt-4o-mini`, `dall-e-3`)
   - состояние включения и кредитный тариф этой конфигурации;
3. после сохранения сразу доступно на фронтенде (для одного типа можно создать несколько конфигураций и переключать их включением/выключением); на странице «Настройка моделей» поддерживаются **импорт / экспорт JSON** — удобно для массового переноса.

Поддерживаемые протоколы:

- **Текст / изображения / TTS**: совместимый с OpenAI (`/chat/completions`, `/images/generations`, `/audio/speech`) или пользовательский эндпоинт (`api_style=custom`)
- **Видео**: настройка эндпоинтов асинхронных задач (отправка → опрос → URL видео); требуется реальный провайдер генерации видео (локальный режим ffmpeg «изображение → видео» отключён)

> На стороне пользователя можно также добавить **приватные модели** в «Личные настройки → Мои модели» (со своим ключом; вызовы не расходуют кредиты), глобальные конфигурации это не затрагивает.
> Локально требуется установить `ffmpeg` (macOS: `brew install ffmpeg`). От него зависит склейка видеоклипов.

## 🔑 Вход и система аккаунтов (локальные, без внешних зависимостей)

Система аккаунтов **встроена в саму систему**: регистрация / вход / смена пароля / обновление сессии — всё идёт через собственный сервер `/api/auth/*`, без каких-либо сторонних центров аккаунтов:

- **Регистрация**: имя пользователя (2–64 символа: буквы, цифры, `_.-`) + пароль (≥6 символов) + email (необязательно); нужно пройти капчу с выбором текста (задания генерирует бэкенд в SVG, `/api/captcha/*`); после успешной регистрации сразу выполнен вход и в подарок начисляется 66 пробных кредитов;
- **Вход**: имя пользователя / email / телефон (любой из них) + пароль; капча проверяется по принципу «проверять, только если передана» (фронтенд по умолчанию её отправляет);
- **Токены**: сервер сам подписывает JWT (префикс `axt_`, access + refresh, refresh не ротируется); фронтенд бесшовно продлевает сессию через `/api/auth/oauth/refresh`; токены админ-панели отдельные (префикс `admt_`);
- **Забыли пароль**: в самостоятельно развёрнутых инстансах нет SMS/email-каналов, самостоятельный сброс не предусмотрен — сброс выполняет администратор в **админ-панели → «Управление пользователями» → сброс пароля**;
- **Блокировка**: после блокировки все выданные токены пользователя становятся недействительными при следующем запросе (сервер при каждом запросе заново проверяет статус пользователя);
- **Вход через сторонние сервисы (опционально)**: в мобильном приложении по-прежнему работает вход в один клик Apple / Google — сервер в режиме прокси с ключами выполняет обмен (`POST /api/auth/oauth/:provider`) и возвращает такую же локальную сессию `axt_`; веб-версии не нужна никакая регистрация колбэков.

Связанные переменные `.env`: `JWT_SECRET`, `ADMIN_JWT_SECRET`, `CAPTCHA_TICKET_SECRET`, `ADMIN_INIT_USERNAME`, `ADMIN_INIT_PASSWORD` (все описаны в комментариях `server/.env.example`).

## 💚 WeChat Pay (V3 · Native по QR-коду / JSAPI)

Настоящий WeChat Pay — **всё управляется конфигурацией и по умолчанию выключено** (если `WECHAT_PAY_*` в `.env` оставлены пустыми, функция не активна, и фронтенд сам скрывает вход в пополнение). `WECHAT_APP_ID` сохранён только как резервное значение для платёжного AppID.

Включите платежи Native/JSAPI в [платформе мерчантов WeChat](https://pay.weixin.qq.com/), получите номер мерчанта и ключ APIv3 и скачайте API-сертификат мерчанта (`apiclient_key.pem` + серийный номер сертификата). **Номер мерчанта и AppID должны быть привязаны друг к другу на платформе мерчантов** (иначе создание заказа вернёт `APPID_MCHID_NOT_MATCH`). Конфигурация:
```bash
WECHAT_PAY_METHOD=native       # native=оплата по QR-коду | jsapi=оплата внутри официального аккаунта (на PC — H5-касса)
WECHAT_PAY_APP_ID=             # AppID, привязанный к номеру мерчанта (если пусто — откат на WECHAT_APP_ID)
WECHAT_PAY_MCH_ID=<ваш номер мерчанта>
WECHAT_PAY_API_V3_KEY=         # 32-значный ключ APIv3
WECHAT_PAY_SERIAL_NO=          # серийный номер API-сертификата мерчанта
WECHAT_PAY_PRIVATE_KEY_PATH=cert/apiclient_key.pem   # путь к apiclient_key.pem на диске (или следующая строка — что-то одно из двух)
WECHAT_PAY_PRIVATE_KEY=        # либо текст PEM прямо инлайн
WECHAT_PAY_NOTIFY_URL=         # если пусто, берётся ${PUBLIC_BASE_URL}/api/recharge/wechat/notify
```
- Процесс: в центре кредитов выбрать «WeChat Pay» → бэкенд создаёт единый заказ (Native возвращает `code_url` для отрисовки QR-кода / JSAPI вызывает оплату) → пользователь платит → асинхронный колбэк WeChat на `/api/recharge/wechat/notify` (расшифровка и проверка AES-256-GCM, идемпотентное зачисление).
- Колбэк должен быть **HTTPS-адресом, доступным из интернета** (на время разработки подойдёт туннель во внутреннюю сеть).

> Шаги вывода в прод (привязка AppID на платформе мерчантов, размещение сертификата локально на сервере, регрессия на реальном заказе на 1 цент) — см. **[deploy/DEPLOY.md](deploy/DEPLOY.md), пункт ⑦ «Шаги запуска WeChat Pay»**.
> База данных: номер транзакции платёжного заказа записывается в `recharge_orders.transaction_id`; столбец досоздаётся идемпотентно через `ensureColumns` при старте, старые базы не затрагиваются.

## 🧪 Шаги сквозной проверки (end-to-end)

0. Админ-панель `/admin` (admin/admin123) → **Настройка моделей** → настройте все четыре типа текст/изображения/видео/TTS (иначе этапы с ИИ будут недоступны)
1. Зарегистрируйтесь/войдите на фронтенде → создайте проект → в «Структуре сценария» вставьте/загрузите сценарий → **разбиение сценария ИИ** (списание кредитов)
2. «Библиотека ассетов» → **извлечение ассетов ИИ** → **сгенерируйте изображения ассетов** для персонажей/сцен
3. «Видео эпизодов» → **сгенерировать скрипт** → перейдите в **редактор раскадровки**
4. В редакторе выберите клип → **сгенерировать сейчас** (видеоклип, первый кадр автоматически станет обложкой предпросмотра)
5. **Соберите полный эпизод** (ffmpeg склеит mp4 целого эпизода)
6. В «Центре кредитов» посмотрите историю операций и пополните баланс; в админ-панели измените тарифы / заблокируйте / сбросьте пароль / посмотрите журнал входов; переключите светлую/тёмную/авто тему

## 📡 Основные API (префикс `/api`, аутентификация JWT, единый формат `{code,message,data}`)

```
POST /auth/register | /auth/login                              # локальная регистрация (нужен ticket капчи) / вход (публичный, ограничение частоты)
POST /auth/password                                            # смена пароля (авторизованная зона)
POST /auth/oauth/refresh                                       # бесшовное продление (refresh_token обменивается на новый access_token, публичный)
POST /auth/oauth/:provider                                     # обмен входа через сторонний сервис на локальную сессию (apple/google/weixin/huawei, опционально)
GET /auth/me   POST /auth/sync                                 # профиль пользователя
POST /captcha/challenge | /captcha/verify                      # капча с выбором текста
GET/POST/PUT/DELETE /projects          GET /projects/:id
POST /projects/:id/script/import       POST /projects/:id/script/parse
POST /projects/:id/extract             GET /projects/:id/assets  POST /assets/:id/generate-image
POST /episodes/:id/generate-storyboard GET /episodes/:id/segments
POST /segments/:id/generate            PUT /segments/:id
POST /episodes/:id/compose             GET /episodes/:id/video
GET /jobs                                                              # центр асинхронных задач (фронтенд опрашивает)
GET /model-configs                     POST /model-configs/import  GET /model-configs/export   # чтение глобальных конфигураций + импорт/экспорт (ведётся в админ-панели)
GET /credits/balance | /credits/transactions
GET /recharge/packages  POST /recharge/create  GET /recharge/orders/:id
POST /recharge/wechat/notify                                   # колбэк WeChat Pay (без аутентификации, проверка подписи + идемпотентность)
GET /showcase/*                                                # витрина (публикация/просмотр/создание по образцу)
GET /market/*                                                  # центр заказов (задания/эскроу/приёмка)
GET /pricing
```
У каждого ИИ-эндпоинта есть парный `…/estimate` для предварительной оценки кредитов; административные эндпоинты (`/admin/*`: пользователи/платежи/задачи/журналы/обслуживание и т.д.) используют отдельный токен админ-панели (`admt_`).

## 🛠 Технологический стек

**Сервер**: Express · Sequelize (два dialect: mysql/sqlite) · JWT · bcrypt · multer · axios · fluent-ffmpeg · sharp
**Веб-клиент**: Vue 3 · Vite · Vue Router · Pinia · Element Plus · vue-i18n · axios (десктоп-оболочка: Electron + electron-updater)

## 📝 Примечания

- Проект поставляется как базис с «полностью работающим сквозным функционалом»: все API и страницы по-настоящему работают и запускаются; UI воспроизводит структуру и состояния референсных макетов.
- Внешние провайдеры (изображения/видео/TTS) требуют настройки реальных ключей в **админ-панели**, чтобы end-to-end получались реальные материалы; ffmpeg используется только для склейки видеоклипов.
- После изменения моделей Sequelize под SQLite удалите `server/data/*.db` и переинициализируйте хранилище (в продакшене рекомендуются миграции).
