# 🎬 星网 XW.COM · แพลตฟอร์มผลิตซีรีส์สั้นด้วย AI

> 🌐 **เดโมออนไลน์**: <https://aiwork.xw.com> 　·　📮 ติดต่อเรา: **kevin@xw.com**

ระบบสร้างสรรค์ซีรีส์สั้นด้วย AI: **นำเข้าบท → ดึงตัวละคร/ฉาก/อุปกรณ์ → สร้างสตอรีบอร์ด → สร้างวิดีโอรายช็อต → ตัดต่อรวมทั้งตอน**.
ฝั่งเซิร์ฟเวอร์เป็น **Node.js + MySQL (หรือ SQLite สำรอง)** ส่วนฝั่งฟรอนต์เป็น **Vue 3 + Element Plus** สองส่วน: **Web (client, รวมหน้าผู้ดูแล client/admin และเชลล์เดสก์ท็อป client/desktop) + มือถือ (uniapp, เชลล์แอป/มินิโปรแกรม/H5)** สื่อสารกันผ่าน REST API ระบบบัญชีผู้ใช้เป็น **การสมัคร/ล็อกอินแบบโลคัลในตัว** (ชื่อผู้ใช้/อีเมล/หมายเลขโทรศัพท์ + รหัสผ่าน) ไม่พึ่งพาศูนย์บัญชีผู้ใช้บุคคลที่สามใด ๆ

## 🚀 เริ่มต้นอย่างรวดเร็ว

### 1. รันเซิร์ฟเวอร์

```bash
cd server
cp .env.example .env          # ค่าเริ่มต้น DB_DIALECT=sqlite รันได้ทันทีโดยไม่ต้องตั้งค่า
npm install
npm run dev                   # http://localhost:3000 สร้างตาราง + seed อัตโนมัติ
```

- **SQLite (พร้อมใช้ทันที, แนะนำสำหรับทดลองในเครื่อง)**: `DB_DIALECT=sqlite` ข้อมูลเก็บที่ `server/data/aidrama.db`
- **MySQL**: ตั้ง `DB_DIALECT=mysql` และกรอก `DB_HOST/DB_PORT/DB_NAME/DB_USER/DB_PASSWORD`
- **การรันครั้งแรกจะสร้างผู้ดูแลเริ่มต้นให้อัตโนมัติ** (คอนโซลจะแสดงข้อความแจ้ง):
  - บัญชีเริ่มต้น **`admin / admin123`** ใช้ล็อกอินหน้าผู้ดูแล `/admin`
  - แทนที่ได้ด้วยตัวแปรสภาพแวดล้อม `ADMIN_INIT_USERNAME` / `ADMIN_INIT_PASSWORD`; หากมีผู้ดูแลอยู่แล้วจะข้ามอัตโนมัติ
  - ⚠️ ก่อนขึ้นโปรดักชันโปรดเปลี่ยนรหัสผ่านเริ่มต้นทันที (`node scripts/setAdminPassword.js` หรือดูหัวข้อหน้าผู้ดูแลด้านล่าง)

### 2. รันไคลเอนต์

```bash
cd client
npm install
npm run dev                   # http://localhost:5173
```

เปิด <http://localhost:5173>: ถ้ายังไม่มีบัญชีให้กด 「สมัครสมาชิก」 (ชื่อผู้ใช้ + รหัสผ่าน ผ่านแคปชาเลือกคำหนึ่งขั้น สมัครสำเร็จคือล็อกอินทันทีและรับเครดิตทดลอง 66 หน่วย); ถ้ามีบัญชีแล้วล็อกอินได้เลย (ชื่อผู้ใช้ / อีเมล / หมายเลขโทรศัพท์อย่างใดก็ได้)

> ไคลเอนต์ตั้งค่าพรอกซีไว้แล้ว `/api` และ `/files` จะส่งต่อไปที่ `http://localhost:3000` อัตโนมัติ

## 🛠 การใช้งานหน้าผู้ดูแล (client/admin)

หน้าผู้ดูแลเป็น **entry แยก, ล็อกอินแยก, โทเคนแยก** (JWT ที่มีคำนำหน้า `admt_` ไม่เกี่ยวข้องกับเซสชันผู้ใช้ฝั่งฟรอนต์):

- **Entry**: <http://localhost:5173/admin> (บนโปรดักชันคือ `https://โดเมนของคุณ/admin`)
- **ล็อกอิน**: บัญชี + รหัสผ่าน + แคปชาเลือกคำ ครั้งแรกใช้ผู้ดูแลเริ่มต้น **`admin / admin123`**;
- **เปลี่ยนรหัสผ่าน**: หน้าผู้ดูแลยังไม่มีหน้าเปลี่ยนรหัสผ่าน ให้รีเซ็ตด้วยสคริปต์ฝั่งเซิร์ฟเวอร์:
  ```bash
  cd server
  node scripts/setAdminPassword.js <ชื่อผู้ใช้หรืออีเมล> <รหัสผ่านใหม่>
  ```
  (การล็อกอินของ `adminAuth` ใช้ชื่อผู้ใช้ / อีเมล / หมายเลขโทรศัพท์อย่างใดก็ได้เป็นบัญชี)

## 🔌 ตั้งค่าโมเดลใหญ่ / มีเดีย (เพื่อให้ฟีเจอร์ AI ใช้งานได้จริง)

ความสามารถ AI ทั้งหมดขับเคลื่อนด้วย **การตั้งค่า** และ **จัดการรวมที่หน้า 「ตั้งค่าโมเดล」 ของหน้าผู้ดูแลทั้งหมด** (`.env` ไม่มีค่าเริ่มต้น LLM ให้อีกต่อไป) เมื่อยังไม่ตั้งค่า: ฟีเจอร์ประเภทข้อความจะแจ้งเตือนก่อนเรียกใช้; ภาพ/วิดีโอ/TTS จะแจ้ง 「ยังไม่ได้ตั้งค่า」 ทันที

ขั้นตอนการตั้งค่า:

1. ล็อกอินหน้าผู้ดูแล `/admin` → **ตั้งค่าโมเดล** → เพิ่มใหม่;
2. เลือกประเภท (ข้อความ / ภาพ / วิดีโอ / TTS) และโปรโตคอล แล้วกรอก:
   - **Base URL** (เช่น `https://api.openai.com/v1`)
   - **API Key** (เก็บเฉพาะฝั่งเซิร์ฟเวอร์ ไม่ส่งลงฟรอนต์)
   - ชื่อโมเดล (เช่น `gpt-4o-mini`, `dall-e-3`)
   - สถานะเปิดใช้และราคาเครดิตของการตั้งค่านั้น;
3. บันทึกแล้วฝั่งผู้ใช้ใช้ได้ทันที (ประเภทเดียวตั้งค่าหลายรายการและสลับเปิด-ปิดได้); หน้า 「ตั้งค่าโมเดล」 รองรับ **นำเข้า / ส่งออก JSON** สะดวกต่อการย้ายเป็นชุด

โปรโตคอลที่รองรับ:

- **ข้อความ / ภาพ / TTS**: ใช้ได้กับ OpenAI (`/chat/completions`, `/images/generations`, `/audio/speech`) หรือ endpoint กำหนดเอง (`api_style=custom`)
- **วิดีโอ**: ตั้งค่า endpoint งานอะซิงโครนัส (ส่งงาน → ถามสถานะ → URL วิดีโอ); ต้องมี provider สร้างวิดีโอจริง (ฟีเจอร์ ffmpeg โลคัล 「ภาพเป็นวิดีโอ」 ปิดใช้งานแล้ว)

> ฝั่งผู้ใช้ยังเพิ่ม **โมเดลส่วนตัว** ได้ที่ 「ตั้งค่าส่วนตัว → โมเดลของฉัน」 (ใส่ Key ของตัวเอง การเรียกใช้ไม่หักเครดิต) ไม่กระทบการตั้งค่าส่วนกลาง
> ต้องติดตั้ง `ffmpeg` ในเครื่อง (macOS: `brew install ffmpeg`) การต่อและตัดต่อคลิปวิดีโอต้องพึ่งพาตัวนี้

## 🚢 ดีพลอยโปรดักชัน

รันบุ๊กฉบับเต็มดูที่ **[deploy/DEPLOY.md](deploy/DEPLOY.md)** (เช็กลิสต์ขึ้น nginx, PM2/systemd แบบอินสแตนซ์เดียว, สำรอง-กู้คืน, ขึ้นระบบ WeChat Pay, งานด้าน compliance ที่ค้างอยู่) ความต้องการสภาพแวดล้อมขั้นต่ำ:

```bash
NODE_ENV=production            # ถ้าไม่ตั้ง JWT จะใช้คีย์สำรองสำหรับ dev เปิดช่องโหว่ด้านความปลอดภัย
JWT_SECRET=<คีย์ลงนามโทเคนเซสชันโลคัล สตริงยาวแบบสุ่ม>      # ระบบนี้ลงนาม/ตรวจสอบเซสชันผู้ใช้เอง (axt_)
ADMIN_JWT_SECRET=<คีย์ลงนามแยกของหน้าผู้ดูแล>
FILE_SIGN_SECRET=<คีย์ลงนามกันขโมยลิงก์มีเดีย>   # ต้องตรงกับคีย์ secure_link ใน deploy/nginx.conf
PUBLIC_BASE_URL=https://your-domain.com
CLIENT_ORIGIN=https://your-domain.com
DB_DIALECT=mysql               # + DB_HOST/DB_PORT/DB_NAME/DB_USER/DB_PASSWORD
```

WeChat Pay ต้องใช้ชุด `WECHAT_PAY_*` อีก 5 ตัว (รหัส merchant, AppID, คีย์ APIv3, เลขซีเรียลใบรับรอง, คีย์ส่วนตัว merchant) ดูที่ `deploy/DEPLOY.md` ⑦

## 🔑 การล็อกอิน & ระบบบัญชีผู้ใช้ (โลคัล ไม่พึ่งภายนอก)

ระบบบัญชีผู้ใช้เป็น **ส่วนในตัวของระบบนี้**: สมัคร / ล็อกอิน / เปลี่ยนรหัสผ่าน / รีเฟรชเซสชันทำผ่าน `/api/auth/*` ของเซิร์ฟเวอร์นี้ทั้งหมด ไม่พึ่งศูนย์บัญชีบุคคลที่สาม:

- **สมัคร**: ชื่อผู้ใช้ (2-64 ตัวอักษรละติน ตัวเลข `_.-`) + รหัสผ่าน (≥6 ตัว) + อีเมล (ไม่บังคับ) ต้องผ่านแคปชาเลือกคำ (ฝั่งแบ็กเอนด์ออกโจทย์เป็น SVG, `/api/captcha/*`); สมัครสำเร็จคือล็อกอินทันที และรับเครดิตทดลอง 66 หน่วย;
- **ล็อกอิน**: ชื่อผู้ใช้ / อีเมล / หมายเลขโทรศัพท์อย่างใดก็ได้ + รหัสผ่าน; แคปชา 「ตรวจเมื่อมีการส่งมา」 (ฟรอนต์ส่งมาให้เป็นค่าเริ่มต้น);
- **โทเคน**: เซิร์ฟเวอร์ลงนาม JWT เอง (คำนำหน้า `axt_`, access + refresh, refresh ไม่มีการหมุนเวียน) ฟรอนต์ต่ออายุเงียบ ๆ ผ่าน `/api/auth/oauth/refresh`; โทเคนหน้าผู้ดูแลแยกต่างหาก (คำนำหน้า `admt_`);
- **ลืมรหัสผ่าน**: อินสแตนซ์ที่ดีพลอยเองไม่มีช่องทาง SMS/อีเมล จึงไม่มีการรีเซ็ตด้วยตนเอง — ให้ผู้ดูแลทำที่ **หน้าผู้ดูแล 「จัดการผู้ใช้」 → รีเซ็ตรหัสผ่าน**;
- **การระงับ**: หลังถูกระงับ โทเคนทุกใบที่ออกให้ผู้ใช้นั้นจะใช้ไม่ได้ตั้งแต่รีเควสถัดไป (เซิร์ฟเวอร์ตรวจสถานะผู้ใช้ใหม่ทุกรีเควส);
- **ล็อกอินบุคคลที่สาม (ทางเลือก)**: ล็อกอินคลิกเดียว Apple / Google บนแอปมือถือยังใช้ได้ — เซิร์ฟเวอร์ถือคีย์ทำพรอกซีแลกเซสชัน (`POST /api/auth/oauth/:provider`) แลกกลับมาเป็นเซสชันโลคัล `axt_` แบบเดียวกัน; ฝั่ง Web ไม่ต้องลงทะเบียน callback ใด ๆ

ตัวแปร `.env` ที่เกี่ยวข้อง: `JWT_SECRET`, `ADMIN_JWT_SECRET`, `CAPTCHA_TICKET_SECRET`, `ADMIN_INIT_USERNAME`, `ADMIN_INIT_PASSWORD` (ดูคำอธิบายใน `server/.env.example`)

## 💚 WeChat Pay (V3 · Native สแกนคิวอาร์ / JSAPI)

WeChat Pay จริง **ขับเคลื่อนด้วยการตั้งค่า, ปิดอยู่โดยค่าเริ่มต้น** (ปล่อยว่าง `WECHAT_PAY_*` ใน `.env` คือยังไม่เปิดใช้ ฟรอนต์จะซ่อนช่องทางเติมเงินอัตโนมัติ) `WECHAT_APP_ID` เก็บไว้เป็นค่าสำรองของ AppID สำหรับชำระเงินเท่านั้น

เปิดใช้ Native/JSAPI บน [WeChat Merchant Platform](https://pay.weixin.qq.com/) รับรหัส merchant คีย์ APIv3 และดาวน์โหลดใบรับรอง API ของ merchant (`apiclient_key.pem` + เลขซีเรียลใบรับรอง) **รหัส merchant และ AppID ต้องผูกกันเสร็จบน merchant platform** (ไม่เช่นนั้นสั่งงานจะขึ้น `APPID_MCHID_NOT_MATCH`) การตั้งค่า:
```bash
WECHAT_PAY_METHOD=native       # native=สแกนคิวอาร์ | jsapi=ชำระใน Official Account (PC ใช้แคชเชียร์ H5)
WECHAT_PAY_APP_ID=             # AppID ที่ผูกกับรหัส merchant (เว้นว่างจะสำรองด้วย WECHAT_APP_ID)
WECHAT_PAY_MCH_ID=<รหัส merchant ของคุณ>
WECHAT_PAY_API_V3_KEY=         # คีย์ APIv3 32 ตัวอักษร
WECHAT_PAY_SERIAL_NO=          # เลขซีเรียลใบรับรอง API ของ merchant
WECHAT_PAY_PRIVATE_KEY_PATH=cert/apiclient_key.pem   # พาธไฟล์ apiclient_key.pem บนดิสก์ (เลือกอย่างใดอย่างหนึ่งกับบรรทัดถัดไป)
WECHAT_PAY_PRIVATE_KEY=        # หรือฝังข้อความ PEM ตรง ๆ
WECHAT_PAY_NOTIFY_URL=         # เว้นว่างจะใช้ ${PUBLIC_BASE_URL}/api/recharge/wechat/notify
```
- ขั้นตอน: เลือก 「WeChat Pay」 ที่ศูนย์เครดิต → แบ็กเอนด์สร้างคำสั่งซื้อรวม (Native คืน `code_url` ไปเรนเดอร์คิวอาร์ / JSAPI เรียกหน้าชำระเงิน) → ผู้ใช้ชำระเงิน → WeChat ยิง callback อะซิงโครนัสมาที่ `/api/recharge/wechat/notify` (ถอดรหัสและตรวจสอบ AES-256-GCM, บันทึกยอดแบบ idempotent)
- callback ต้องเป็น **ที่อยู่ HTTPS ที่เข้าถึงได้จากอินเทอร์เน็ตสาธารณะ** (ช่วงพัฒนาใช้ NAT tunneling แทนได้)

> ขั้นตอนขึ้นระบบ (ผูก AppID บน merchant platform, วางใบรับรองลงเซิร์ฟเวอร์, ทดสอบย้อนกลับด้วยออเดอร์จริง 1 เซ็น) ดูที่ **[deploy/DEPLOY.md](deploy/DEPLOY.md) ⑦ ขั้นตอนเปิดใช้ WeChat Pay**
> ฐานข้อมูล: เลขที่คำสั่งซื้อชำระเงินเขียนลง `recharge_orders.transaction_id` เติมให้แบบ idempotent โดย `ensureColumns` ตอนสตาร์ต ไม่กระทบฐานข้อมูลเดิม

## 🧪 ขั้นตอนตรวจสอบ end-to-end

0. หน้าผู้ดูแล `/admin` (admin/admin123) → **ตั้งค่าโมเดล** → ตั้งค่าให้ครบ 4 ประเภท ข้อความ/ภาพ/วิดีโอ/TTS (ไม่เช่นนั้นขั้นตอน AI ใช้ไม่ได้)
1. สมัคร/ล็อกอินฝั่งผู้ใช้ → สร้างโปรเจกต์ใหม่ → 「โครงเรื่องบท」 วาง/อัปโหลดบท → **AI แบ่งบท** (หักเครดิต)
2. 「คลังแอสเซ็ต」 → **AI ดึงแอสเซ็ต** → **สร้างภาพแอสเซ็ต** ของตัวละคร/ฉาก
3. 「วิดีโอรายตอน」 → **สร้างสคริปต์** → เข้า **ตัวแก้สตอรีบอร์ด**
4. ในตัวแก้ เลือกช็อต → **สร้างทันที** (คลิปวิดีโอ พร้อมดึงเฟรมแรกเป็นภาพปกพรีวิวอัตโนมัติ)
5. **ตัดต่อรวมทั้งตอน** (ffmpeg ต่อออกมาเป็น mp4 ทั้งตอน)
6. ที่ 「ศูนย์เครดิต」 ดูประวัติรายการและเติมเงิน; ที่หน้าผู้ดูแลแก้ราคา / ระงับผู้ใช้ / รีเซ็ตรหัสผ่าน / ดูบันทึกล็อกอิน; สลับธีมสว่าง/มืด/อัตโนมัติ

## 📡 API หลัก (พรีฟิกซ์ `/api`, ยืนยันตัวตนด้วย JWT, รูปแบบเดียว `{code,message,data}`)

```
POST /auth/register | /auth/login                              # สมัครแบบโลคัล (ต้องมีแคปชา ticket) / ล็อกอิน (สาธารณะ, จำกัดอัตรา)
POST /auth/password                                            # เปลี่ยนรหัสผ่าน (ต้องล็อกอิน)
POST /auth/oauth/refresh                                       # ต่ออายุเงียบ ๆ (refresh_token แลก access_token ใหม่, สาธารณะ)
POST /auth/oauth/:provider                                     # ล็อกอินบุคคลที่สามแลกเซสชันโลคัล (apple/google/weixin/huawei, ทางเลือก)
GET /auth/me   POST /auth/sync                                 # โปรไฟล์ผู้ใช้
POST /captcha/challenge | /captcha/verify                      # แคปชาเลือกคำ
GET/POST/PUT/DELETE /projects          GET /projects/:id
POST /projects/:id/script/import       POST /projects/:id/script/parse
POST /projects/:id/extract             GET /projects/:id/assets  POST /assets/:id/generate-image
POST /episodes/:id/generate-storyboard GET /episodes/:id/segments
POST /segments/:id/generate            PUT /segments/:id
POST /episodes/:id/compose             GET /episodes/:id/video
GET /jobs                                                              # ศูนย์งานอะซิงโครนัส (ฟรอนต์ถามสถานะเอง)
GET /model-configs                     POST /model-configs/import  GET /model-configs/export   # ฝั่งอ่านการตั้งค่าส่วนกลาง + นำเข้า/ส่งออก (จัดการที่หน้าผู้ดูแล)
GET /credits/balance | /credits/transactions
GET /recharge/packages  POST /recharge/create  GET /recharge/orders/:id
POST /recharge/wechat/notify                                   # callback WeChat Pay (ไม่ต้องยืนยันตัวตน, ตรวจลายเซ็น + idempotent)
GET /showcase/*                                                # ศูนย์โชว์เคส (เผยแพร่/เรียกดู/ทำตามแบบ)
GET /market/*                                                  # ศูนย์รับงาน (ใบงาน/วางกำมือ/ตรวจรับ)
GET /pricing
```
API AI แต่ละตัวมี API `…/estimate` คู่กันสำหรับประมาณการเครดิต; API ฝั่งจัดการ (`/admin/*`: ผู้ใช้/การชำระเงิน/งาน/บันทึก/บำรุงรักษา ฯลฯ) ใช้โทเคนหน้าผู้ดูแลแยกต่างหาก (`admt_`)

## 🛠 เทคโนโลยีที่ใช้

**เซิร์ฟเวอร์**: Express · Sequelize (รองรับ 2 dialect mysql/sqlite) · JWT · bcrypt · multer · axios · fluent-ffmpeg · sharp
**เว็บ**: Vue 3 · Vite · Vue Router · Pinia · Element Plus · vue-i18n · axios (เชลล์เดสก์ท็อป: Electron + electron-updater)
**มือถือ**: uni-app (แอป / เชลล์มินิโปรแกรม / H5)

## 📝 หมายเหตุ

- โปรเจกต์นี้ส่งมอบฐานที่ 「ฟีเจอร์ใช้งานได้ครบ end-to-end」: API และหน้าจอทั้งหมดทำงานจริงและรันได้; UI จำลองโครงสร้างและสถานะตามภาพอ้างอิง
- Provider ภายนอก (ภาพ/วิดีโอ/TTS) ต้องตั้งค่า key จริงใน **หน้าผู้ดูแล** จึงจะได้วัตถุดิบจริงแบบ end-to-end; ffmpeg ใช้เพื่อการต่อและตัดต่อคลิปวิดีโอเท่านั้น
- หลังแก้โมเดล Sequelize ถ้าใช้ SQLite ให้ลบ `server/data/*.db` แล้วเตรียมข้อมูลใหม่ (ฝั่งโปรดักชันแนะนำใช้ migration)
