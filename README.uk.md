# 🎬 星网 XW.COM · Платформа для створення AI-серіалів

> 🌐 **Онлайн-демо**: <https://aiwork.xw.com> 　·　📮 Зв'яжіться з нами: **kevin@xw.com**

Система для створення коротких серіалів за допомогою AI: **імпорт сценарію → вилучення персонажів/сцен/реквізиту → генерація сторіборду → генерація відео за сторібордом → компіляція повного епізоду**.
Серверна частина — **Node.js + MySQL (з відкатом до / SQLite)**, клієнтська — **Vue 3 + Element Plus** у двох варіантах: **Web (client, включно з адмін-панеллю client/admin та десктопною оболонкою client/desktop) + мобільний (uniapp, оболонки App/мініпрограма/H5)**, які спілкуються через REST API. Система акаунтів — **вбудована локальна реєстрація/вхід** (ім'я користувача/електронна пошта/телефон + пароль), без залучення жодного стороннього центру акаунтів.

## 🚀 Швидкий старт

### 1. Запуск серверної частини

```bash
cd server
cp .env.example .env          # Типове DB_DIALECT=sqlite — працює без жодних налаштувань
npm install
npm run dev                   # http://localhost:3000 , автоматичне створення таблиць + seed
```

- **SQLite (працює одразу, рекомендовано для локального ознайомлення)**: `DB_DIALECT=sqlite`, дані зберігаються у `server/data/aidrama.db`
- **MySQL**: встановіть `DB_DIALECT=mysql` і заповніть `DB_HOST/DB_PORT/DB_NAME/DB_USER/DB_PASSWORD`
- **При першому запуску автоматично створюється початковий адміністратор** (у консолі з'явиться підказка):
  - Типовий акаунт **`admin / admin123`** — для входу в адмін-панель `/admin`
  - Можна перевизначити змінними середовища `ADMIN_INIT_USERNAME` / `ADMIN_INIT_PASSWORD`; якщо адміністратор уже існує, крок пропускається
  - ⚠️ Перед запуском у продакшн негайно змініть типовий пароль (`node scripts/setAdminPassword.js`, або див. розділ про адмін-панель нижче)

### 2. Запуск клієнта

```bash
cd client
npm install
npm run dev                   # http://localhost:5173
```

Відкрийте <http://localhost:5173>: якщо акаунта немає — натисніть «Реєстрація» (ім'я користувача + пароль, пройти CAPTCHA на вибір тексту; після успішної реєстрації ви одразу увійшли та отримали 66 пробних кредитів); якщо акаунт уже є — просто увійдіть (ім'я користувача / пошта / телефон).

> Клієнт має налаштований проксі: `/api` та `/files` автоматично пересилаються на `http://localhost:3000`.

## 🛠 Адмін-панель (client/admin)

Адмін-панель — це **окремий вхід, окремий вхід, окремий токен** (JWT із префіксом `admt_`, який ніяк не перетинається з сесіями користувачів фронтенду):

- **Вхід**: <http://localhost:5173/admin> (у продакшні — `https://ваш-домен/admin`)
- **Вхід до системи**: акаунт + пароль + CAPTCHA на вибір тексту. При першому запуску використовуйте початкового адміністратора **`admin / admin123`**;
- **Зміна пароля**: окремої сторінки зміни пароля в панелі поки немає — скористайтеся серверним скриптом:
  ```bash
  cd server
  node scripts/setAdminPassword.js <ім'я користувача або пошта> <новий пароль>
  ```
  (вхід `adminAuth` приймає як акаунт ім'я користувача / пошту / телефон)

## 🔌 Налаштування LLM / медіа (щоб AI-функції запрацювали насправді)

Усі AI-можливості **керуються конфігурацією** і **обслуговуються централізовано на сторінці «Налаштування моделей» в адмін-панелі** (`.env` більше не містить жодних типових налаштувань LLM). Якщо конфігурації немає: текстові функції попередять перед викликом; зображення/відео/TTS одразу повернуть помилку «не налаштовано».

Кроки налаштування:

1. Увійдіть в адмін-панель `/admin` → **Налаштування моделей** → додати;
2. Оберіть тип (текст / зображення / відео / TTS) і протокол, заповніть:
   - **Base URL** (наприклад `https://api.openai.com/v1`)
   - **API Key** (зберігається лише на сервері, не передається на фронтенд)
   - **Назва моделі** (наприклад `gpt-4o-mini`, `dall-e-3`)
   - Стан увімкнення та кредитну ціну цієї конфігурації;
3. Після збереження фронтенд може одразу ним користуватися (однотипних конфігурацій може бути кілька з перемиканням увімкнено/вимкнено); на сторінці «Налаштування моделей» доступні **імпорт / експорт JSON** для пакетного перенесення.

Підтримувані протоколи:

- **Текст / зображення / TTS**: сумісний з OpenAI (`/chat/completions`, `/images/generations`, `/audio/speech`) або власний ендпоінт (`api_style=custom`)
- **Відео**: налаштовується ендпоінт асинхронних завдань (надіслати → опитувати → URL відео); потрібен реальний постачальник генерації відео (локальний ffmpeg «зображення → відео» вимкнено)

> Користувач також може додати **приватну модель** у «Особисті налаштування → Мої моделі» (зі своїм ключем; виклики не списують кредитів), це не впливає на глобальну конфігурацію.
> Потрібен локально встановлений `ffmpeg` (macOS: `brew install ffmpeg`). Від нього залежить склеювання відеофрагментів.

## 🔑 Вхід і система акаунтів (локальна, без зовнішніх залежностей)

Система акаунтів — **вбудована в цю систему**: реєстрація / вхід / зміна пароля / оновлення сесії повністю обслуговуються власним сервером через `/api/auth/*`, без жодного стороннього центру акаунтів:

- **Реєстрація**: ім'я користувача (2-64 символи: літери, цифри, `_.-`) + пароль (≥6 символів) + пошта (необовʼязково), потрібна CAPTCHA на вибір тексту (завдання у вигляді SVG від бекенда, `/api/captcha/*`); успішна реєстрація означає вхід і нарахування 66 пробних кредитів;
- **Вхід**: ім'я користувача / пошта / телефон + пароль; CAPTCHA «перевіряється, лише якщо надіслана» (фронтенд надсилає її за замовчуванням);
- **Токени**: сервер сам підписує JWT (префікс `axt_`, access + refresh, refresh не ротується), фронтенд непомітно оновлює сесію через `/api/auth/oauth/refresh`; токен адмін-панелі окремий (префікс `admt_`);
- **Забутий пароль**: у саморозгорнутих інстансах немає каналів SMS/пошти, самостійне відновлення не передбачене — це робить адміністратор через **адмін-панель «Керування користувачами» → Скидання пароля**;
- **Блокування**: після блокування всі вже видані токени користувача стають недійсними вже при наступному запиті (сервер при кожному запиті повторно перевіряє статус користувача);
- **Сторонній вхід (за бажанням)**: в мобільному застосунку досі працює вхід в один клік через Apple / Google — сервер проксує обмін ключами (`POST /api/auth/oauth/:provider`) і повертає той самий локальний `axt_`-сеанс; для Web не потрібно жодної реєстрації callback-ів.

Пов'язані `.env`: `JWT_SECRET`, `ADMIN_JWT_SECRET`, `CAPTCHA_TICKET_SECRET`, `ADMIN_INIT_USERNAME`, `ADMIN_INIT_PASSWORD` (усі описані в коментарях `server/.env.example`).

## 💚 WeChat Pay (V3 · Native QR / JSAPI)

Справжній WeChat Pay, **керується конфігурацією і типово вимкнений** (якщо `WECHAT_PAY_*` у `.env` порожні — не активований, фронтенд автоматично ховає кнопку поповнення). `WECHAT_APP_ID` зберігається лише як запасне значення для платіжного AppID.

Активуйте Native/JSAPI-платежі на [платформі торговців WeChat](https://pay.weixin.qq.com/), отримайте ідентифікатор merchant і ключ APIv3, а також завантажте API-сертифікат торговця (`apiclient_key.pem` + серійний номер сертифіката). **Ідентифікатор merchant та AppID обовʼязково має бути привʼязані на платформі торговців** (інакше при створенні заказу буде помилка `APPID_MCHID_NOT_MATCH`). Конфігурація:
```bash
WECHAT_PAY_METHOD=native       # native=QR-код | jsapi=оплата всередині офіційного акаунта (PC — через H5-касa)
WECHAT_PAY_APP_ID=             # AppID, привʼязаний до ідентифікатора merchant (якщо порожньо — відкат до WECHAT_APP_ID)
WECHAT_PAY_MCH_ID=<ваш ідентифікатор merchant>
WECHAT_PAY_API_V3_KEY=         # 32-символьний ключ APIv3
WECHAT_PAY_SERIAL_NO=          # Серійний номер API-сертифіката торговця
WECHAT_PAY_PRIVATE_KEY_PATH=cert/apiclient_key.pem   # Шлях до apiclient_key.pem на диску (або наступний рядок — щось одне)
WECHAT_PAY_PRIVATE_KEY=        # Або просто вбудований PEM-текст
WECHAT_PAY_NOTIFY_URL=         # Якщо порожньо, береться ${PUBLIC_BASE_URL}/api/recharge/wechat/notify
```
- Процес: у центрі кредитів обрати «WeChat Pay» → бекенд створює заказ (Native повертає `code_url` для показу QR-коду / JSAPI піднімає оплату) → користувач сплачує → асинхронний callback WeChat на `/api/recharge/wechat/notify` (перевірка підпису з розшифруванням AES-256-GCM, ідемпотентне зарахування).
- Callback має бути **публічно доступною HTTPS-адресою** (у розробці можна тунелювати у внутрішню мережу).

> Кроки запуску (привʼязка AppID на платформі торговців, сертифікат на сервері локально, регрес на справжньому заказі в один цент) — у **[deploy/DEPLOY.md](deploy/DEPLOY.md) ⑦ Кроки запуску WeChat Pay**.
> База даних: номер заказу платежу записується в `recharge_orders.transaction_id`, який ідемпотентно доповнюється `ensureColumns` при старті і не впливає на старі бази.

## 🧪 Кроки наскрізної перевірки

0. Адмін-панель `/admin` (admin/admin123) → **Налаштування моделей** → налаштуйте всі чотири категорії: текст/зображення/відео/TTS (інакше AI-кроки недоступні)
1. Фронтенд: реєстрація/вхід → новий проєкт → «Структура сценарію»: вставити/завантажити сценарій → **AI розбиває сценарій** (списує кредити)
2. «Бібліотека активів» → **AI вилучає активи** → **генерація зображень активів** для персонажів/сцен
3. «Відео серій» → **генерація сценарію** → перейти до **редактора сторіборду**
4. У редакторі обрати фрагмент → **згенерувати зараз** (відеофрагмент + автоматичне витягнення першого кадру як превʼю-обкладинки)
5. **Компіляція епізоду** (ffmpeg склеює повний mp4 епізоду)
6. У «Центрі кредитів» перегляньте історію та поповніть баланс; в адмін-панелі змініть тарифи / заблокуйте / скиньте пароль / подивіться журнал входів; перемкніть світлу/темну/автоматичну тему

## 📡 Основні API (префікс `/api`, JWT-авторизація, єдиний `{code,message,data}`)

```
POST /auth/register | /auth/login                              # Локальна реєстрація (потрібен CAPTCHA ticket) / вхід (відкрито, з обмеженням частоти)
POST /auth/password                                            # Зміна пароля (для авторизованих)
POST /auth/oauth/refresh                                       # Непомітне оновлення (refresh_token → новий access_token, відкрито)
POST /auth/oauth/:provider                                     # Обмін стороннього входу на локальний сеанс (apple/google/weixin/huawei, за бажанням)
GET /auth/me   POST /auth/sync                                 # Профіль користувача
POST /captcha/challenge | /captcha/verify                      # CAPTCHA на вибір тексту
GET/POST/PUT/DELETE /projects          GET /projects/:id
POST /projects/:id/script/import       POST /projects/:id/script/parse
POST /projects/:id/extract             GET /projects/:id/assets  POST /assets/:id/generate-image
POST /episodes/:id/generate-storyboard GET /episodes/:id/segments
POST /segments/:id/generate            PUT /segments/:id
POST /episodes/:id/compose             GET /episodes/:id/video
GET /jobs                                                              # Центр асинхронних завдань (фронтенд опитує)
GET /model-configs                     POST /model-configs/import  GET /model-configs/export   # Читальна частина глобальних конфігурацій + імпорт/експорт (обслуговується в адмін-панелі)
GET /credits/balance | /credits/transactions
GET /recharge/packages  POST /recharge/create  GET /recharge/orders/:id
POST /recharge/wechat/notify                                   # Callback WeChat Pay (без авторизації, перевірка підпису + ідемпотентність)
GET /showcase/*                                                # Центр шоукейсу (публікація/перегляд/зробити те саме)
GET /market/*                                                  # Центр заказів (завдання/екскроу/приймання)
GET /pricing
```
У кожного AI-ендпоінта є відповідний `…/estimate` для попередньої оцінки кредитів; адмін-ендпоінти (`/admin/*`: користувачі/платежі/завдання/журнали/обслуговування тощо) використовують окремий адмін-токен (`admt_`).

## 📝 Примітки

- Цей проєкт поставляє базовий «наскрізнь робочий функціонал»: усі API та сторінки справді працюють і запускаються; UI відтворює структуру та стани референсних макетів.
- Зовнішні постачальники (зображення/відео/TTS) потребують налаштування справжніх ключів в **адмін-панелі**, щоб наскрізь отримувати справжні матеріали; ffmpeg використовується лише для склеювання відеофрагментів.
- Після зміни моделей Sequelize під SQLite видаліть `server/data/*.db` і виконайте повторну ініціалізацію (у продакшні рекомендуються міграції).
